# 机队地图

**Map** 把你的机队显示为一个个地点而不是一行行记录：每个节点都在它所处的场地上，并按状态着色。

列表告诉你某个节点失联了。地图告诉你*现在是哪栋楼没人看着*，而这才是事故发生时人们真正会问的问题。

## 放置节点 {#placing}

刚接管的节点会先出现在 **Unplaced nodes** 里。把它拖到地图上即可放置。

在你这么做之前，它只是列表里的一行而不是一个地点——所以说，节点没上地图，接管其实就还没真正完成。

当节点彼此靠得很近时，它们会聚合成簇。要把某一个节点从簇里挪出来，请**放大**；在低缩放级别下，你
拖动的是整个群组，而不是那台设备。

## 读懂标记 {#legend}

| 颜色 | 含义 |
|---|---|
| **Online** | 已连接并在上报。 |
| **Cert expiring** | 仍在工作，但证书快到期了。 |
| **Lost** | 未连接。 |
| **Idle** | 已接管，暂无内容可报。 |

「Cert expiring」单独占一种颜色，是因为它是你还来得及预防的那种故障——参见
[管理节点](managing-nodes#certificate)。

## 底图，以及在没有互联网时如何工作 {#basemap}

地图由两个互不依赖的部分组成：**你的数据**（节点、建筑、点位）和**底图**（下方的街道与地形）。

你的数据始终可用。底图是一份由控制平面自己提供的 **PMTiles** 文件；没有它时，地图会显示
*no offline basemap installed — showing node positions only*。那是一张功能受限的地图，而不是坏掉的
地图：标记、建筑和楼层平面图都照常可用，只是背后没有街道而已。

这种拆分正是整个设计的核心。隔离的控制平面无法像网页地图那样按需从互联网抓取瓦片，所以瓦片必须就在
**设备本地**。

## 下载某个区域 {#region-download}

如果控制平面确实能访问互联网，你可以把某个区域提取到本地底图中：先设置一次远程 PMTiles 源 URL，然后
下载你当前查看的区域。

动手前有两件事要知道：

- **下载会通过互联网访问那个 URL。** 在本应没有任何外发流量的场地上，这恰恰是不该做的事——请改为
  安装事先准备好的底图文件。
- **服务器上必须装有 `pmtiles` 工具。** 如果没有，页面会说明这一点，并且在装上之前下载都会失败。

如果因为区域太大而被拒绝，请放大之后分块下载。

## 从地图进入建筑 {#indoor}

已放置的建筑可以打开它的**楼层平面图**，从那里你看到的是钉在房间里的摄像机，而不是街道上的图钉。

这条下钻路径值得记住：场地 → 建筑 → 楼层 → 摄像机，这正是人们口头描述一个位置的方式，现在也成了你
导航的方式。参见[建筑与楼层平面图](buildings-and-floors)。

## 场地 {#sites}

场地把同一地点的所有东西归到一起。按场地筛选地图可以一次只处理一个地方；在多地点机队中，用场地来
保持可读性——报告也可以按场地生成，道理是一样的。
