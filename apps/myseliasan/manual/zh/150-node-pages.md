# 在节点内部操作

对某个节点点击 **Manage**，就会在这个控制平面内部打开该节点自己的页面：它的仪表盘、摄像机、事件，
以及——取决于它是哪种设备——它的设备、门禁或告警规则。

你的浏览器从不连接节点。所有内容都走节点向外拨号建立的控制通道，正因如此，位于 NAT 之后的远程站点
设备才有可能从这里操作。

## 不同类型的节点分别能看到什么 {#kinds}

**摄像机录像机**显示它的仪表盘、摄像机、事件和远程控制台。

**传感器网关**显示它的设备、告警规则、告警日志、设备类型和开通配置。

**门禁控制器**显示它的门以及门的通行权限。

这些页面是节点真实的界面，而不是它们的摘要：一切都是从节点本身读取的，也是写到节点本身的。

## 实时视频 {#video}

摄像机图块承载**全动态实时画面**，经节点的安全媒体通道中继，再通过 WebRTC 重新广播到你的浏览器。

无法建立 WebRTC 的图块会自动退化为大约每 1.5 秒一张的快照。那是画面降级而不是故障，而且它通常是
网络在告诉你一些关于它自己的事情。

至于节点能做的全部事情——那些没有在这里呈现的界面——**Open node UI** 会直接前往设备自己的界面。

## 由节点决定你能做什么 {#authorization}

这一点值得弄明白，因为它和大多数人的预期不一样。

你*访问*某个节点页面的权限来自这个控制平面。而你在那里*执行操作*的权限，是由**节点自己**根据你的
[节点访问权限](users-and-roles#node-access)来判定的——viewer、operator 或 admin。

所以你在这些页面里遇到的拒绝并不是从这里发出的。以传感器网关为例：viewer 能看到设备及其当前读数；
operator 还能看到遥测历史并确认告警；admin 才能向设备下发命令。请去申请在那个节点上更高的授权，而
不是在这里申请一个更宽泛的角色。

有一条实际保证值得明确说出来：当节点拒绝一条命令时，**什么都没有被发送**。它会明确告知，而设备
从始至终未被触碰。

## 空白页面可能意味着不可达 {#offline}

如果节点处于离线状态，这些页面就没有东西可读。

界面会明确说明这一点，而这个区别比听上去更重要：*这里的空白页面意味着不可达，而不是「没有内容」*。
一份因为控制器被拔掉而空空如也的门列表，看起来和一台确实没有配置门的控制器一模一样，而这两者中
只有一个是你今天必须处理的问题。

## 远程控制台 {#remote}

**Remote** 直接通过隧道调用节点的 API。

它是那些嵌入页面未覆盖内容的应急出口。节点依然会执行它自己的授权——只读权限会拒绝写操作——所以这个
控制台不能被用来绕过授权。

流式端点（实时视频、server-sent events）**无法通过隧道传输**，在这里不会工作；这类内容请使用摄像机
图块或节点自己的界面。

## 当节点页面加载不出来时 {#troubleshooting}

1. **节点离线。** 上面所有功能都需要它处于连接状态。
2. **你没有节点访问权限**，或者级别不够——那个拒绝来自节点。
3. **它是一个流式端点**，而隧道不承载这类请求。
4. **节点在线但很慢。** 这些页面是通过隧道对另一台机器发起的实时调用，而不是保存在这里的缓存副本。
