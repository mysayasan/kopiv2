# 设置编辑器

**Settings** 让你从应用内部编辑控制平面自身的配置。改动会写入 `config.json`，并在**重启之后**生效。

只有**超级管理员**可以查看或修改这些内容，而且这不是一条你可以下放的矩阵规则：这些值决定了控制平面
如何验证人员身份、以及如何访问你的机队。

## 先保存，再重启 {#restart}

保存只是记录改动，并不会让它生效。页面随后会告诉你需要重启，并提供 **Restart now**。

这种拆分是刻意的。一次在请求进行到一半时生效的配置修改，会在已经在途的会话脚下改变规则——诚实的做法
是写入文件、明确告知，然后在你准备好时重启。这也意味着你可以一次做几处相关改动，只付出一次重启的
代价。

执行时请预期应用会短暂不可用。

## 你可以在这里编辑什么 {#sections}

| 分区 | 涵盖内容 |
|---|---|
| **Local Login** | 单点登录不可用时使用的内置管理员账号。 |
| **Single Sign-On** | 通过 myidsan 身份提供方进行的联合登录。 |
| **Connectivity** | 节点发现、接管，以及机队访问本控制平面所用的端口。 |
| **Security** | 令牌、TLS 证书、内容安全策略、API 限流。 |
| **Storage & Cache** | 上传文件的存储及其清理，以及缓存后端。 |
| **Logging & Telemetry** | 应用与 API 日志、保留期，以及指标端点。 |
| **AI Agent** | 每日摘要和可选的语言模型——参见[配置语言模型](language-model)。 |
| **System** | 当前运行版本和进程控制。 |

## 有意不放在这里编辑的内容 {#not-here}

这里是配置的一个**安全子集**。数据库连接、服务器监听设置和引导行为都无法从应用中编辑。

这是刻意设定的边界，而不是疏漏：如果数据库设置的一个拼写错误是通过「需要数据库才能运行的那个应用」
保存下去的，你最后会得到一台起不来的设备，而且没有任何界面可供修复。那些值留在文件里，修复它们不
依赖于应用本身是否健康。

## 机密 {#secrets}

机密字段留**空表示保持当前值**，而不是清空它。

已保存的机密永远不会回显给你，所以留空意味着「未更改」而不是「置为空」——正因如此，你才能在不重新
输入某个可能并不在手边的密钥的情况下，去修改旁边的字段。

## 恢复默认值 {#defaults}

每个分区都可以恢复为其原始值。这同样需要重启才能生效，而且它是按分区进行的操作，不是整份配置的重置。

当某个分区被调成了没人能解释清楚的状态时，这就是正确的做法——从出厂值开始，一次只改一样东西。

## 如果改动之后控制平面起不来了 {#recovery}

改完设置之后应用起不来，几乎总是因为文件里有一个错误的值，而修复它的地方也正是那个文件。在这里编辑
的配置最终会落到应用数据目录下的 `config.json`。

如果某次改动导致控制平面无法启动，那个文件就是恢复路径：在磁盘上更正或删除有问题的值，然后重新启动
它。这个编辑器只是一份始终可读、可手工修复的文件之上的便利层，而这恰恰是你在「便利层不可用的那天」
最需要的特性。
