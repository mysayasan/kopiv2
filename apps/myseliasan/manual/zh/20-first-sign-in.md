# 首次登录

## 引导账户 {#bootstrap}

MySeliaSan 首次启动时会创建一个 **superadmin** 账户，密码是**为这一次安装生成的**。没有随产品发布、
可供查阅的默认密码，任何两次安装也不会共用同一个密码。

密码会出现在两个地方，你可以按自己运行控制平面的方式去找：

- **在控制台上。** 启动时会打印一段横幅，包含要打开的地址、用户名和密码。在 Docker 里它位于
  `docker logs`；在 Linux 上位于服务日志中。
- **在文件里。** 一个凭据文件被写入数据目录——当控制台已经滚过去，或者服务在没有可见窗口的情况下运行
  时，用这个。

> [!NOTE]
> 如果你在首次启动前设置了 `config.json` 中的 `localAuth`，或环境变量 `LOCAL_ADMIN_PASSWORD`，
> 则会改用那个密码，并且**不会**在任何地方显示。横幅会指向你的配置，而不是把你已经拥有的机密再打印
> 一遍。

该账户被标记为*必须修改密码*，所以登录后你看到的第一件事就是修改密码的界面。先输入一次性密码，再把
你自己的密码输入两遍。

## 这个账户是临时的 {#handover}

引导 superadmin 的存在只是为了让你能进来。它不该是你用来管理整片资产的账户，首次运行向导里专门有一
个**移交**步骤来处理这件事。

预期的终局是：真实的人以自己的身份登录，引导账户被停用。在那之前，审计日志中的每一次操作都会记在一
个共享账户名下，这让审计日志远不如它应有的那样有用。

参见[首次运行设置向导](setup-wizard#handoff)。

## 用你自己的身份服务器登录 {#sso}

MySeliaSan 可以把身份验证交给 **MyIDSan**，这样人们就用自己已经拥有的账户登录。

你不需要把连接信息输入两遍。MyIDSan 的 Apps 页面会把它为这个控制平面注册的客户端导出成一个小的 JSON
文件；在这里导入该文件，颁发者、受众、客户端 ID 和重定向 URL 就会被完全按照 MyIDSan 写下的内容填好。
两个控制台，一份事实来源。

如果你没有运行身份服务器，跳过即可——本地账户照常可用，你随时可以稍后再接。

> [!NOTE]
> 跳转到 MyIDSan 登录是浏览器唯一一次离开控制平面的地方，而它仍然留在你自己的网络内部。这条路径上没有
> 任何一环会访问互联网。

## 日常登录 {#daily}

登录界面会把你带到本地账户表单，或者带出去到你的身份服务器，取决于控制平面的配置方式。它周围有两个
控件，都会记在这台浏览器上：

- **语言切换器**——英语、马来语、中文和阿拉伯语。阿拉伯语会镜像整个布局。
- **帮助链接**，打开本手册。它在你登录之前就能用，而那正是你最可能需要它的时候。

## 登录失败时 {#troubleshooting}

- **"你的账户没有角色"**——真实账户存在，但还没有人给它分配角色。这是有意为之：新用户从一无所有开始，
  而不是继承访问权限。管理员在"角色与访问"下设置它。
- **反复失败会锁定该地址**，锁定时长随每次尝试递增。等倒计时走完；没有人能缩短它。**账户**与地址是
  分开计数的，因此别人在其他地方猜测你的用户名也会把你锁在门外，即使你一次都没输错。这是阻止分散在
  大量地址上的猜测攻击所要付出的代价，而且只要有人正确登录一次就会解除。在修改密码页面更改自己的密码
  也按同样方式计数：反复输错*当前*密码同样会触发锁定。
- **从身份服务器重定向回来失败**——通常是控制平面不信任的证书，或者重定向 URL 没有完全匹配。重新导入
  SSO 包，而不要手动重打这些字段。
