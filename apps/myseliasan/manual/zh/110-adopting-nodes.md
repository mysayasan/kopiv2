# 接管节点

接管是唯一一个横跨两个产品的流程，正因如此它值得认真读一遍而不是靠猜。它分三步完成：共享密钥、表示同意、
执行接管。

## 1. 生成机队密钥 {#fleet-key}

在这里生成一次**机队密钥**，并把它粘贴到你打算接管的每一台设备上——在 MyMataSan 节点上是
**Settings → Connectivity**。

正是这把密钥让节点变得可被发现：发现探测包用它签名，所以**只有持有同一把密钥的控制平面才能看见这个节点**。
没有密钥，节点根本不回应发现。

这就是它的安全属性，而它是双向的：把机队密钥当成密码看待。任何持有它的人都能在本地网络上找到并尝试接管
你的设备。

## 2. 从节点取得认领码 {#claim-code}

在节点上生成一个**认领码**。它的有效期很短，这是刻意的。

这套两步握手是有意设计的。密钥说明*你属于哪支机队*；认领码说明*而且我此刻同意*。两者单独都不够，所以一把
被窃取的密钥无法悄无声息地吞并别人的设备。

## 3. 接管 {#adopt}

回到这里，**Discover** 会扫描本地网络寻找未配对的节点，并列出所有回应的设备。选中节点，输入它的认领码，
然后接管。名称默认取节点的主机名——请改成人们会挂在嘴边说出来的名字。

发现看不到的节点可以改用**按地址**接管，这也是跨子网时的常规做法。

## 一个控制平面，永久绑定 {#single-parent}

被接管的节点会**锁定到唯一一个控制平面**，并彻底停止回应发现。

正是这一点阻止了同一网络上的第二个控制平面悄悄接管一台已经归属他人的设备。不存在"被两支机队接管"这种状态，
这也是为什么已被接管的节点永远不会出现在 Discover 里。

## 发现不到任何设备时 {#troubleshooting}

按可能性从高到低：

1. **节点没有机队密钥**，或者持有的是另一把。没有匹配的密钥时发现就是静默的，这是设计使然——这是最常见的
   原因，且遥遥领先。
2. **节点已被接管**，被这个控制平面或另一个。它已经静默了。检查它自己的 Connectivity 页面。
3. **节点在另一个子网或 VLAN 上。** 发现使用组播，而路由器默认不转发组播。改用按地址接管。
4. **认领码已过期。** 重新生成一个。
5. **防火墙正在丢弃发现流量。**

发现看不到的节点，并不等于你接管不了的节点。发现只是便利手段；按地址接管始终有效。

## 释放节点 {#releasing}

从这里**释放**它——这是干净的路径，能让这个控制平面的记录保持一致。

如果这个控制平面已经不在或无法访问，节点可以改为从它自己的 Connectivity 页面**自行脱离**。无论哪种方式，
节点都会重新变得可被发现，而这个控制平面会失去访问权。如果某个节点自行脱离了，请在这里清理掉那条残留记录。

## 接管之后 {#after}

节点的摄像机、健康状态和告警会立即开始汇总上来。接下来有两件事值得做：

- **把它放到地图上**——放在它所属的场所，如果你有楼层平面图也放到图上。在你这么做之前，它只是清单里的一行，
  而不是一个地点。
- **检查谁能看到它。** 对节点的访问权是按角色授予的，所以新接管的节点不会自动对所有人可见。

## 端口，以及远端场所为什么能用 {#ports}

机队流量使用它自己的端口，与 Web 界面分开：发现是本地网络上的组播，节点到控制平面的通道则使用机队自有
证书颁发机构签发的证书进行双向认证。

节点是**向外拨出**的。因此远端场所 NAT 后面的节点不需要入站端口转发，而这通常正是决定那个场所究竟能否被
远程管理的关键。
