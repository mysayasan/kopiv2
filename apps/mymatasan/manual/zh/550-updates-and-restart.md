# 更新、重启与健康检查

**设置 → 版本与健康**涵盖正在运行的版本、更新、重启、运行时依赖和服务健康。

## 正在运行的版本 {#version}

版本、共享内核版本、提交号和构建日期都显示在这里以及页脚。

报告问题时请把这一整组都写上。"最新那个"不是版本，而同一版本号下两次构建之间的差异，恰恰是识别回归所
需的信息。

## 更新 {#updating}

如何更新取决于设备是怎么安装的，标签页会告诉您属于哪种情况：

- **应用内更新。** 更新会在这里提供并应用。
- **由包管理器管理。** 用您平台的工具更新——
  `sudo apt update && sudo apt install --only-upgrade mymatasan` 或 `dnf` 的等价命令。应用内更新被
  有意禁用，好让包管理器保持为唯一事实来源。
- **容器。** 拉取新镜像并重建容器。

任何更新之前：

1. **做一次[配置备份](backup-and-restore)。**
2. **确认您的[恢复密钥](encryption-at-rest#export)已导出且校验通过。**
3. 在有人能盯着的时候更新，而不是周五傍晚。

更新会重启设备。实时画面中断、录像在重启期间停止，正在进行的检测会丢失。在繁忙站点这就是一分钟的画面
缺失——请据此安排时间。

## 重启 {#restart}

**重启应用**会干净地重启：录像器被正确停止，分段得以收尾而不是被截断。

当某项设置标注*（重启后生效）*时请重启——刚安装的 ffmpeg 是常见情形——以及当设备出现您无法解释的异常
时。它是安全的，也是一个正当的首选诊断手段。

请始终从这里重启，而不是杀掉进程。突兀的停止可能让正在写入的分段没有收尾。

## 运行时依赖 {#dependencies}

标签页会报告设备所依赖的东西是否就位：

- **ffmpeg**——实时画面、录像和 AI 取帧路径。没有它什么都不工作。
- **AI 运行时**——Python 加检测库。没有它就完全没有检测。
- **OCR 依赖**——专门用于[车牌](fire-smoke-and-plates#lpr)。

每一项都可以在应用内安装。每当某整块能力似乎缺失而不只是配置不当时，请先看这个标签页——"这台安装上检测
从来就没工作过"通常是缺运行时，而不是规则写坏了。

## 存活与就绪 {#health}

两种健康信号，含义不同：

- **存活（liveness）**——进程有响应。监督程序据此决定是否重启设备。
- **就绪（readiness）**——在此之上，数据库和缓存可达。负载均衡器据此决定是否把流量发过来。

应用自己的监控——主机健康、摄像机健康——以**建议性**就绪字段的形式出现。它们从不阻断就绪，因为一台摄像
机离线并不构成把录像机撤出服务的理由。降级的数值仍然值得调查；只是它不算一次服务中断。

如果您要接入外部监控，请用存活看"它还活着吗"，用就绪看"它能提供服务吗"，用通知信息流看"有没有出问
题"——第三个恰好覆盖前两个被设计成不去覆盖的东西。
