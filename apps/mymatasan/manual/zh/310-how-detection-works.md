# 检测是如何工作的

读懂这一篇比手册中任何其他一篇都更省时间，因为几乎每一个"AI 判断错了"的问题，实质上都是"哪一层出了
问题"。

## 处理链 {#chain}

1. 从摄像机的检测码流中取出一**帧**。
2. 每个**活动模型**都看这一帧，并报告它识别出的对象，每个对象带有一个**标签**（`person`、`car`、
   `truck`……）、一个**框**，以及一个 0 到 1 之间的**置信度**。
3. 这些原始标签被映射到您命名的**对象类别**——*人员*、*车辆*、*配送*。
4. 该摄像机上的每条**规则**判断：所见之物、所在位置、发生时间以及把握程度，是否值得产生一条**告警**。

模型产出事实，规则施加判断。把两者分开，诊断就变得简单：

- **它根本没看见那个东西** → 模型或置信度阈值。
- **它看见了但没告警** → 规则：区域、时段、类别选择、最少帧数。
- **它对不该报的东西告警** → 几乎总是规则：区域太大或阈值太低。

## 模型 {#models}

**基础（内置）模型**始终开启。它识别常见的日常类别——人、车辆、动物等等。它的大小是速度与准确度之间
的直接取舍：

| 变体 | 特点 |
|---|---|
| Nano | 最快，最不准。默认值，也是 CPU 或树莓派上的正确选择。 |
| Small | 稍慢一点，明显更好。 |
| Medium | 明显更慢。建议配 GPU。 |
| Large | 在 CPU 上很慢。建议配 GPU。 |
| Extra-large | 最慢，最准。强烈建议配 GPU。 |

**自定义模型**与基础模型并行运行，而不是取而代之。正因如此，您为某个特定对象训练的模型才能与通用检测
共存。

代价是按模型、按帧计算的：每个活动模型都会对每一帧做推理。两个活动模型大约就是一个的两倍工作量。在一
台配置一般的机器上同时开启大号基础模型*和*两个自定义模型，就是系统变迟钝的常见解释。

已知的基础模型变体会在首次使用时下载并缓存，因此那一次下载需要联网。之后一切都在本地。

## 标签与对象类别 {#labels}

模型输出的是**原始标签**——像 `person`、`car`、`fire hydrant` 这样的小写词。那是模型的词汇表，而且是精
确匹配的：没有任何活动模型产出的标签永远匹配不到东西，而拼错的标签会悄无声息地什么也匹配不到。

您不用原始标签写规则。您用自己定义的**对象类别**写规则，它把一个易读的名字映射到一个或多个原始标签
——*车辆* = `car`、`truck`、`bus`、`motorcycle`。参见[对象类别与分组](object-classes)。

## 置信度 {#confidence}

置信度是模型有多确定。规则的**阈值**是它能接受的下限。

没有正确的取值，只有您在选择的取舍：

- **更低**能抓到更多真实事件，也抓到更多误报。
- **更高**更安静，也漏得更多。

从默认值附近开始，观察一天告警日志，再去调它。要*基于您看到的情况*去调，而不是凭原则。对着明亮、近距
离、无遮挡门口的摄像机可以用高阈值；对着一条又长又暗车道的摄像机不行，硬套只会让它永不触发。

## 最少帧数 {#min-frames}

对象必须连续出现在多少帧中，规则才会触发。

这是对付闪烁——阴影、飞蛾、压缩伪影——最有效的单一控件，因为噪声很少跨帧持续，而真人总是持续存在。把它
从 1 提到 2 或 3，能消除大部分虚假告警，代价只是零点几秒。

## 冷却时间 {#cooldown}

规则触发之后，它会保持安静这么多秒。

没有它，一个人站在门口，只要他站着，每一次检测都会产生一条告警。冷却时间把"一件事正在发生"转换成"一
件事发生过"，而这才是一条通知应有的含义。

## 帧从哪里来 {#frames}

检测读取的是摄像机的**检测**码流，由您在摄像机的[码流标签页](camera-properties#stream)分配。它不必是
您录像用的那一路。

请使用子码流。检测器不需要 4K 才能认出一个人，而子码流与主码流之间的开销差距，往往就是一台机器扛得住
与扛不住的差别。例外是[车牌](fire-smoke-and-plates#lpr)，它需要尽可能多的像素。

## 它做不到什么 {#limits}

- **它不理解意图。** 它认得一个人；它分不清送货司机和入侵者。区域、时段和类别就是您补充这层语境的方式。
- **摄像机看不到的，它也看不到。** 没有任何模型能从昏暗、潮湿、逆光或失焦的画面里还原细节。摄像机的
  安装位置每一次都胜过模型的大小。
- **它不是人。** 每一个阈值都是概率。请在"有些告警是错的、有些事件会漏掉"这个前提上建立您的流程，因为
  两者都会发生。
