# 通过 ONVIF 管理摄像机

摄像机的 **ONVIF** 标签页管理的是摄像机本身，而不是本设备如何使用它。它省去了为常做的那几件事专门去
摄像机 Web 界面跑一趟。

这里的一切都需要可用的摄像机凭据，以及支持相应操作的摄像机。标签页会显示每台摄像机声明了什么，因此某
个控件不存在，就意味着固件没有提供它。

## 身份 {#identity}

厂商、型号、固件版本、硬件与序列标识、MAC 地址、ONVIF 版本，以及摄像机声明的服务。

两个实际用途。**固件版本**是当一台摄像机与旁边一模一样的另一台表现不同时，第一个要查的东西。**MAC
地址**是当摄像机 IP 变动后，您在交换机或 DHCP 服务器里找到它的依据。

## 时钟 {#clock}

读取摄像机当前时间，并可设置时间来源。

- **NTP（自动）**——摄像机从时间服务器同步。请用这个。
- **手动**——保存时把摄像机时钟设为本设备的当前时间。

同时可见：时区、夏令时处理，以及 NTP 服务器是来自 DHCP 还是显式设置。

这件事比看起来重要得多。**时钟错误的摄像机会产出时间戳错误的录像**，而当您要把录像与门禁记录或证人陈
述对上时，一台差十一分钟的摄像机比没有摄像机更糟。如果您在这个标签页只改一件事，就改这个——而且要在每
一台摄像机上改，不只是您正在看的这台。

## 网络 {#network}

读取摄像机的 IP 配置并可更改：DHCP 开关、IPv4 地址、前缀长度、网关和 DNS 服务器。

> [!WARNING]
> 错误的地址、前缀或网关会让摄像机不可达，而唯一的退路通常是物理复位按钮。设备正是为此要求您确认。

如果您希望摄像机使用固定地址，在服务器上做 DHCP 保留比在摄像机上设静态地址更安全。它能挺过摄像机的恢
复出厂，而且是在一个您仍然够得着的地方修改。

如果您确实要设静态地址，请从同一子网内的机器上操作，并在关闭页面之前确认摄像机在新地址上有应答。

## 摄像机用户 {#users}

摄像机自己的 ONVIF 账号：列出、新增、改密码、移除。角色是摄像机的——Administrator、Operator、User。

有用的做法是给本设备一个专用的非管理员账号，权限刚好够推流以及您需要的管理操作，而把摄像机的管理员登
录留给人使用。录像机的密码需要变更时，恰好只有一处会变，而摄像机自己的日志也会告诉您哪次访问来自录像
机。

## 维护 {#maintenance}

**重启**会重启摄像机。对于能应答但推流不正常的摄像机，这是正确的第一步，代价是一分钟的画面。

**软复位**把摄像机恢复为默认值但保留网络设置。摄像机仍然可达；它的配置文件、凭据和图像设置则不会保留。

**硬复位**恢复完整出厂默认值，**包括网络**。摄像机很可能会以不同的地址回来——本来是静态的可能变成
DHCP——您也许得重新发现它。不要对一台您够不着的摄像机远程执行此操作。

任何复位之后，请重新检查摄像机的[码流标签页](camera-properties#stream)：配置文件通常会被重新编号，本
设备原先使用的分配已不再指向您以为的地方。

## ONVIF 控件缺失或失败时 {#limits}

- **控件没有显示。** 摄像机没有声明该服务。请用它自己的 Web 界面。
- **控件显示了但失败。** 通常是账号权限不足——ONVIF 的 operator 账号往往无法更改网络设置。请改用摄像
  机上的管理员账号重试。
- **该标签页上的一切都失败。** 先怀疑已保存的凭据；参见
  [摄像机健康](camera-health#troubleshooting)。
