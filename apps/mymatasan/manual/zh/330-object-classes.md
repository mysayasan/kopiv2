# 对象类别与分组

**对象 → 类别**下的注册表，是把模型的词汇表变成您的词汇表的地方。它就是规则的**检测**选择器所提供的
那份清单。

## 类别 {#categories}

**类别**把一个易读的名字映射到一个或多个原始模型标签。

*车辆*可能包含 `car`、`truck`、`bus` 和 `motorcycle`。检测*车辆*的规则于是匹配其中任意一个，而您永远
不必记住模型用的是哪个词。

存在两种：**对象类别**（人、车辆……）和**危险类别**（火焰、烟雾），它们是同一套机制，只是按所表示的内
容加以区分。

## 标签 {#labels}

标签是模型精确的输出词，而"精确"就是这里的全部关键：

- 精确匹配。是 `fire hydrant`，不是 `fire_hydrant`。
- 只有当产出该标签的模型处于**活动**状态时，标签才会检测到东西。当没有任何运行中的模型产出某类别的标
  签时，注册表会把该类别标记为**模型未激活**。
- 拼错的标签永远匹配不到，也永远不会报错。它就那样待着，什么也检测不到。

请从列表中搜索并选取，不要手打。那份列表就是您的活动模型实际产出的标签集合，因此从中选取是唯一能确保
正确的方式。

您训练的模型带来的标签，会在该模型于**设置 → AI** 中被激活后出现在这里。

## 分组 {#groups}

**分组**把若干类别打包在一起。以该组为目标的规则匹配其中任意一个。

例如 *交通* = *车辆* + *人员* + *自行车*。当几个类别在您的规则里总是结伴出现时，分组就派上用场——定义
一次，规则就保持可读。

## 把训练出的标签归入已有类别 {#filing}

这是值得知道的一招。

当您用自己的标签训练模型时——比如为某辆特定车辆用 `papa`——它默认会以自己的名义成为一个顶级类别。通常
这不是您想要的：您想让它在所有已经用到*车辆*的地方都算作*车辆*。

编辑已有类别并把该标签加进去。它就不再是一个独立的顶级类别，而每一条已经在检测*车辆*的规则都会自动把
它算进来，无需任何改动。

## 实践中的形态 {#practice}

让注册表保持小而有意义。为您会写规则的每一样东西建一个类别，而不是为模型能产出的每一个标签建一个。

最终有三十个类别的站点，通常其中三个在用，二十七个只是让规则选择器变得没法读。注册表是给您的规则用的
词汇表——如果您不会在对讲机里说出它，它多半就不需要成为一个类别。
