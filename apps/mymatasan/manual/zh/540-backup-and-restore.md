# 备份您的配置

配置备份是一个用口令保护的 `.mmbackup` 文件，保存着您的**设置**，好让一台新机器无需重新配置就能起来。

在**设置 → 备份与恢复**中创建和恢复。首次配置向导也提供恢复这一侧——参见
[从备份恢复](restore-from-backup)。

## 选择包含什么 {#sections}

四个部分，可分别勾选：

| 部分 | 内容 |
|---|---|
| **摄像机** | 摄像机与 ONVIF 条目（含已保存凭据），以及每台摄像机的录像配置。 |
| **AI 检测** | 检测规则与对象类别注册表。 |
| **通知** | 送达目标，包括 Telegram、Webhook 和 MQTT 的机密。 |
| **应用设置** | 解码、视觉与抓帧设置；摄像机健康与主机健康配置。 |

除非有理由，否则四项全选。部分备份适用于在机器之间搬运配置的某一部分——比如把调好的通知配置搬到第二台
设备上。

## 从不包含什么 {#excluded}

**您的录像。** 备份是配置，不是归档。录像、截图和告警历史留在产生它们的机器上。

**这台机器的身份。** 静态加密密钥、机群配对与注册、mTLS 证书、`config.json` 以及"配置已完成"标记从不
导出——因此备份不能被用来把一台设备的身份克隆到另一台上。

**自定义模型权重。** 只被引用，不被嵌入。请另行拷贝 `.pt` 文件。

**本地用户账号。** 请在新机器上重建。

实际后果是：一次完整重建需要*三*样东西——配置备份、[恢复密钥](encryption-at-rest#export)，以及录像本
身。少了任何一样，都会留下别的东西补不上的缺口。

## 口令 {#passphrase}

该文件携带正常 API 从不输出的明文机密：摄像机密码、机器人令牌、代理凭据。它总是用您设定的口令加密，而
**该口令无法找回**。

由于加密基于口令而不绑定生成它的机器，该文件可以在任何主机上打开。这既让它适合迁移，也让它一旦泄露就
很危险。请把这个文件当作机密对待。

## 恢复 {#restoring}

载入文件、输入口令，并在应用任何内容之前先**预览**它包含什么。然后选择：

- **替换**——覆盖文件中包含的那些部分。这些部分中当前配置的内容将不复存在。
- **合并**——把文件的内容追加到已有内容之后。

当把一个站点的摄像机并入一台已在看守其他站点的设备时，合并是安全的选择。当把机器重建到一个已知状态
时，替换才是您想要的。

两种模式下，记录之间的引用都会在插入行时重新指向，因此即使内部 id 变了，规则仍然挂在正确的摄像机上。

## 恢复之后 {#after}

1. **重启。** 录像、检测和通知服务在启动时采用的是旧配置，不重启就不会采用恢复后的配置。首次配置路径
   会明确提示这一步。
2. **确认凭据到位。** 摄像机密码随文件一同迁移；请确认摄像机确实上线，而不是想当然。
3. **补做备份带不了的部分**——加密密钥、机群配对、用户账号、自定义模型文件。

## 什么时候做备份 {#when}

- 首次配置完成、站点配置就绪之后。
- 任何重大变更之后——新增摄像机、改写规则、新增送达目标。
- 升级或更换硬件之前。

备份很小，保存它没有成本。请多留几份：在一次错误配置之后做的备份会忠实地保存那次错误配置，而唯一的退
路是更早的那一份。

## 恢复失败时 {#troubleshooting}

几乎总是以下两者之一，而设备无法告诉您是哪一个：

- **口令错误**——文件根本无法解密。
- **该文件不是备份**，或在传输中被截断。

请重新拷贝文件并再试一次口令。口令丢失的备份，按设计，任何人都打不开。
