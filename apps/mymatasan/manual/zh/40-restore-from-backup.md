# 从备份恢复

配置备份是一个 `.mmbackup` 文件，保存着某次安装的**设置**——它的摄像机、检测规则、通知目标、运行时
配置。恢复它，可以让一台全新的机器接管这一切，而不必再手工配置第二遍。

## 文件里有什么、没有什么 {#contents}

一个备份可以包含以下四个部分中的任意几个：

| 部分 | 包含内容 |
|---|---|
| **摄像机** | 摄像机与 ONVIF 条目（含已保存的凭据），以及每台摄像机的录像配置。 |
| **AI 检测** | 检测规则及其引用的类别注册表。 |
| **通知** | 送达目标，包括 Telegram、Webhook 和 MQTT 的机密。 |
| **应用设置** | 解码、视觉与抓帧设置；摄像机健康与主机健康配置。 |

有两样东西是刻意不包含的。

**您的录像。** 备份是配置，不是归档。录像、截图和警报历史留在产生它们的那台机器上。

**这台机器的身份。** 静态加密密钥、机群配对与注册、mTLS 证书、`config.json` 以及"配置已完成"标记，
从不导出。这是有意为之：它意味着备份不能被用来把一台设备的身份克隆到另一台上。

> [!WARNING]
> 该文件包含正常 API 从不交出的明文凭据——摄像机密码、机器人令牌、代理机密。它用您选择的口令加密，
> 而那个口令是保护它的唯一屏障。请把这个文件当作机密对待，并据此选择口令。

由于加密基于口令而不绑定生成它的机器，该文件可以在任何主机上打开。这既是它对迁移有用的原因，也是它
一旦泄露就很危险的原因。

## 在首次配置期间恢复 {#during-setup}

在向导的"欢迎"步骤上选择**从备份恢复**，选取文件并输入口令。

这条路径会直接应用备份，替换全新安装原有的内容。没有预览——在一台全新的机器上，没有什么可以拿来对比
权衡。然后：

1. 恢复报告成功。
2. **重启以生效。** 这不是可选项。录像、检测和通知服务是针对旧的空配置启动的，不重启就不会采用恢复后
   的配置。设备回来之后页面会自行刷新。
3. 向导不会再次出现。恢复过的机器被视为已完成配置。

之后请检查备份无法携带的东西：静态加密及其恢复密钥，以及本节点若隶属某个控制平面时的机群配对。

## 恢复到运行中的安装 {#into-running}

在已经配置好的设备上，请改从**设置 → 备份与恢复**恢复。那条路径会在应用任何内容之前先预览文件内容，
并提供两种模式：

- **替换**会覆盖文件中包含的那些部分。这些部分中当前配置的内容将不复存在。
- **合并**会把文件的内容追加到已有内容之后。

当您要把一个站点的摄像机并入一台已经在看守其他站点的设备时，合并是安全的默认选择。当您要把机器重建
到一个已知状态时，替换才是您想要的。

无论哪种模式，记录之间的引用都会在插入行时重新指向，因此即使摄像机的内部 id 变了，规则仍然挂在正确
的摄像机上。

## 恢复失败时 {#troubleshooting}

几乎每一次失败都是以下两者之一，而设备无法告诉您是哪一个：

- **口令不对。** 文件根本无法解密。
- **该文件不是备份**，或在传输中被截断。

请重新下载或重新复制文件，再试一次口令。口令丢失的备份无法打开——按设计，没有任何恢复途径。
