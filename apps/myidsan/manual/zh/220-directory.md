# 接入目录服务

MyIDSan 可以对照你已在运行的 LDAP 或 Active Directory 服务器校验密码，让人们用手上已有的域账户登录，而不是再记
第二个。**目录服务**界面用于配置它，而且始终只有一个目录。

## MyIDSan 从目录取什么、不取什么 {#scope}

它取**认证**——密码对不对——以及**用户组归属**。它不会把你的目录复制进自己的数据库，也不会向你的目录写入。
MyIDSan 保留的账户是一个本地外壳，承载角色和审计历史；凭据仍留在它原来的地方。

目录账户的密码从不被存储。*用户的*密码除了用于校验的那次绑定之外，也从不被看到。

## 填写表单 {#form}

- **服务器主机**和**端口**，明文端口升级用 **StartTLS** 打开，隐式 TLS（`ldaps`）则关闭。
- **固定的 CA 证书** — 如果目录的证书由你自己的机构签发，把 PEM 粘贴进来。连接失败通常就是这个原因。
- **服务账户绑定 DN** 和**密码** — MyIDSan 用来查找用户的只读账户。该密码只写：留空即保留已存的那个，这样保存
  其他无关改动时不必重新输入机密。
- **基础 DN** — 从哪里开始搜索。
- **用户过滤器** — 其中 `%s` 代表正在查找的用户名。
- **组属性** — 承载用户所属组的属性。在 Active Directory 上通常是 `memberOf`。
- **主体属性** — 在账户**整个生命周期内**标识它的属性。见下文；这是最值得一次就设对的字段。
- **登录选项标签** — 登录界面上按钮的措辞。对必须去点它的人来说，"域账户"胜过"LDAP"。

**测试连接**使用表单中当前的设置运行，而不是已保存的设置，因此你可以在提交前先验证一次改动。给它一个示例用户名，
它会报告找到的组——那正是你写任何映射之前需要的东西。

> [!IMPORTANT]
> 请把主体属性选成**不可变**的东西——对象 GUID，而不是邮箱地址或用户名。回访者是按它匹配的，而按一个可以被换新的
> 东西匹配，意味着一次改名会把别人的账户交给他们，或者让他们被丢在一个没有角色的新账户里。

## 把组映射到角色 {#mapping}

目录中的组本身在这里不授予任何东西。添加一条映射——组的 DN 或名称，映射到一个角色，带一个优先级——该组中的人就会
获得那个角色。

- 当某人同时属于多个已映射的组时，**优先级最高的胜出**。
- **没有匹配到任何映射并不是拒绝。** 那个人会成功登录，然后落到等待放行界面，和任何新账户一样。参见
  [用户、角色与用户组](users-roles-groups#pending)。

**目录为权威**决定了*第二次*登录时会发生什么。打开它，映射会在每次登录时重新应用：在这里手工设置的角色会被覆盖，
在目录中被移出某个组的人下次登录时会失去该组授予的角色。关闭它，映射只播种一次角色，本地修改会保留。

当访问权实际上是由目录决定时就打开它——那正是接入目录的意义。只有当你打算在这里管理角色时才让它关着，并且要坦白：
把某人移出域中的组并不会移除他们的访问权。

## 目录账户的第二重验证 {#mfa}

强制 MFA 的策略**不会**扩展到目录账户，除非你同时打开*应用于目录账户*。这个默认值是有意的：那些用户的验证方式
策略通常属于域，在这里强制一次会与域已经要求的东西重复。参见
[第二重验证与账户找回](second-factor#policy)。

## 当它不工作时 {#troubleshooting}

- **连接失败** — 最常见的是证书。要么固定 CA 的 PEM，要么检查 StartTLS 是否与你给的端口相符。测试连接会报告底层
  错误，而不是一个笼统的失败。
- **绑定成功但没有返回任何组** — 组属性不对，或者目录不为该账户填充它。有些服务器不会填充 `memberOf`，除非该组
  本身属于会维护它的类型。
- **所有人都落到等待放行** — 映射什么也没匹配上。用一个示例用户名跑一次测试，然后复制它实际返回的组字符串。

对这个界面的每一次改动都会写入[审计日志](audit-log)，包括主机、基础 DN 和权威标志——绝不包括绑定密码。
