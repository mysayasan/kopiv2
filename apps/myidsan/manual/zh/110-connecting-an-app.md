# 接入应用

通过 MyIDSan 登录用户的应用称为**依赖方应用**。注册在**应用**界面完成，需要四样东西：一个代码、一个受众、一个
基础 URL，以及至少一个重定向 URI。

## 实际发生了什么 {#flow}

这里没有任何东西是登录时临时编造的。应用带着你注册的值把用户的浏览器送到 MyIDSan；MyIDSan 走完自己的各道关卡，
再把浏览器带着一个一次性授权码送回去；应用的**服务端**用浏览器从未见过的密钥，把那个授权码换成用户的身份。

```seq
title : 一次登录，从依赖方应用的角度看
actor app : 你的应用
actor browser : 用户的浏览器
actor idsan => first-sign-in#gates : MyIDSan
app -> browser : 这里没有人登录——去问一下
browser -> idsan : 请求授权，附上你的客户端 id、受众、重定向 URI 和你生成的 state
idsan -> browser : 登录界面，以及它背后的每一道关卡
browser -> app : 回到你的重定向 URI，带回一个一次性授权码和你的 state
app -> idsan : 用你的客户端密钥兑换该授权码
idsan --> app : 他们是谁、持有什么角色、有效多久
```

有两个后果值得直说：

- **密钥是服务端对服务端使用的。** 如果你的应用是没有自有后端的单页应用，它就没有安全的地方保存密钥，也无法完成
  这次兑换。
- **授权码是一次性的。** 同一个授权码的第二次兑换会被拒绝，并作为一次拒绝记入[审计日志](audit-log)。授权码重放
  就是这个样子，而且它本来就应该被看见。

## 填写表单 {#form}

- **代码** — 应用的简短标识：小写字母、数字和连字符，以字母开头。它是应用的稳定句柄，之后无法更改。
- **受众** — 签发令牌上盖的 `aud`。本套件的惯例是它与代码一致，表单会让它跟随代码直到你手动编辑。受众与代码不同
  是合法的，只是必须明确写出来。
- **基础 URL** — 应用所在的位置。`http://` 只对 `localhost` 接受；其他任何明文 HTTP 都会被标记，因为重定向携带
  着授权码。
- **重定向 URI** — MyIDSan 把浏览器送回去的地方。**它是精确匹配的**：协议、主机、端口、路径、末尾斜杠，全部算数。
  已注册的 `https://app.example.com/api/auth/callback` 不匹配
  `https://app.example.com/api/auth/callback/`。本套件自己的应用把它挂在 `/api/auth/callback`。

界面右侧显示**实时的授权 URL**和一段根据你已输入内容生成的配置片段。请读那里而不是本页：它们由本服务器自身的地址
和你的真实取值生成，因此不可能过时。

## 客户端密钥 {#secret}

在应用界面生成密钥。MyIDSan 只存储它的哈希——API 从不返回它，它的明文**只存在于生成它的那个浏览器标签页里**。

这有一个实际后果：在离开页面之前复制它，或者导出配置包。如果丢了，你只能轮换而不是找回，而在用新密钥重新配置之前，
该应用无法让任何人登录。轮换会记入审计日志。

## 把这些值交出去 {#export}

与其在两个控制台之间重新输入客户端 id 和受众，不如用应用界面上的**导出**。它会写出一个小的 JSON 文件，包含签发方、
受众、提供方基础 URL、客户端 id、重定向基址和路径，以及会话有效期——密钥也在内，但只有在同一个标签页里刚刚生成过
的情况下才有。文件会说明它属于哪种情况，而不是悄悄给出一个注定用不了的配置包。

MySeliaSan 可以在它的设置界面直接导入该文件：它会把表单填好，然后等你保存。两个控制台，一个事实来源。

## 各段有效期 {#lifetimes}

```spec
title : 出厂时这次交换各部分的有效期
row code `300s` : 授权码。它只需要撑过重定向返回和你的应用随即发起的兑换，所以有意设得很短。
row token `900s` : 交给你的应用的访问令牌。
row session `259200s` : 在这里的登录本身——三天。这就是为什么在多个应用之间切换不会再次要求密码，也是决定一枚被盗会话 cookie 能值多久的那个数字。
```

每一项都可以在应用界面按应用单独覆盖，那正是为某个敏感应用缩短时长而不影响所有人的正确位置。

> [!NOTE]
> 三天的会话也正是[提级重新认证](sessions-and-step-up#stepup)存在的原因。从未锁屏的笔记本上取走的 cookie 能用三天；
> 提级认证就是让它无法用于修改角色和导出身份库的那道防线。

## 当它不工作时 {#troubleshooting}

几乎每次失败都是这四种之一，而审计日志会指明是哪一种：

- **`redirect_uri is not registered`** — 精确匹配失败。逐字符比较这两个字符串，包括末尾斜杠。
- **未知的客户端** — 代码或客户端 id 与任何已注册且启用的应用都不匹配。检查该应用是否被设为停用。
- **密钥不对** — 通常是轮换只落到了一边。
- **授权码已被使用** — 要么是真正的重放，要么是你的应用在超时后重试了兑换。请重跑整个授权跳转，而不是重试兑换。

以上每一种都会作为拒绝写入[审计日志](audit-log#federation)，并带上被拒绝时针对的应用。那是首先要看的地方——你的
应用只能看到它自己的报错。
