# 首次登录

## 初始账户 {#bootstrap}

MyIDSan 第一次启动时会创建一个 **superadmin** 账户，密码是**为这次安装单独生成的**。没有随产品发布、可供查阅的
默认密码，也没有两次安装共用同一个。

密码会被放在两个地方，无论你以哪种方式运行这台服务器都能找到：

- **在控制台上。** 启动时会打印一段横幅，包含要打开的地址、用户名和密码。在 Docker 中是 `docker logs`；在
  Linux 上是服务日志。
- **在文件里。** `INITIAL_ADMIN_LOGIN.txt` 会写入数据目录，只有运行服务器的那个账户可读。当控制台已经滚过去，
  或服务作为没有可见窗口的 Windows 服务运行时，用它。**登录之后请删除它。**

> [!NOTE]
> 如果你在首次启动前设置了 `config.json` 中的 `localAuth` 或环境变量 `LOCAL_ADMIN_PASSWORD`，则会改用那个密码，
> 并且**不会**在任何地方回显。横幅会指向你的配置，而不是打印一个你已经掌握的机密。

该账户被标记为*必须修改密码*，所以登录后你看到的第一个界面就是修改密码界面。输入那个一次性密码，然后把你自己的
密码输入两次。

## 登录成功不等于已经到达 {#gates}

正确的密码能给你一个会话，但不一定能给你工作区：有四件各自独立的事情可能把你留在专门的界面上，而且它们的检查
顺序是固定的。知道这个顺序，通常就是"我登录了却卡住了"的全部答案。

```flow
title : 为什么正确的密码仍可能把你留在专门的界面上
step creds : 你输入用户名和密码
ask locked : 该地址近期失败次数过多？
end lockout : 拒绝，直到倒计时结束
ask factor => second-factor : 该账户是否已经有第二重验证？
step code => second-factor : 输入验证器应用的验证码，或一个恢复码
ask pwd : 密码是否被标记为必须修改？
step change : 先设置一个你自己的密码
ask enrol => second-factor#policy : 策略是否要求该账户尚不具备的验证方式？
step enrolnow => second-factor#enrol : 先注册一个验证器
ask role => users-roles-groups#pending : 有人给这个账户分配角色了吗？
end pending => users-roles-groups#pending : 等待放行——需要管理员分配一个
ok workspace : 工作区，只显示你的角色可以打开的内容
creds -> locked
locked -> lockout : 是
locked -> factor : 否
factor -> code : 是
factor -> pwd : 否
code -> pwd
pwd -> change : 是
pwd -> enrol : 否
change -> enrol
enrol -> enrolnow : 是
enrol -> role : 否
enrolnow -> role
role -> pending : 否
role -> workspace : 是
```

让人意外的是最后两个。**注册验证器**是在密码通过*之后*才要求的，而不是取代密码——策略是要你"添加"一个验证方式，
而不是证明一个你还没有的，因此启用该策略不会把尚未注册的管理员锁在门外。**放行**不是故障：新账户一开始完全没有
角色，而不是继承一个，所以必须有人授予。

## 锁定，以及它实际锁住的是谁 {#lockout}

反复失败会把**来源地址**锁定一段时间，且每次重复都会延长。每次失败还会付出一点固定延迟，无论该账户是否存在——这是
有意为之，使响应时间无法被用来推断哪些用户名是真实的。

```spec
title : 出厂时的登录策略
row minlength `12 characters` : 一个人可以选择的最短密码。字符类别规则（大写、小写、数字、符号）默认全部关闭——更长的口令胜过加了个符号的短密码。与用户名相同的密码始终被拒绝，无论其他配置如何。
row attempts `8` : 单个地址被锁定前允许的失败次数。
row window `300s` : 统计这些失败的时间窗口。
row lockout `60s` : 第一次锁定的时长。每次重复翻倍。
row lockoutmax `3600s` : 锁定时长能增长到的上限。
row delay `400ms` : 加在每次失败尝试上，使错误的用户名和错误的密码被拒绝所需的时间相同。
```

这六项都可以在**设置 › 登录**下修改。改动之前有两件事值得知道：锁定阈值不能低于两次尝试（设为一次会让账户在第一个
笔误上就被锁定），密码长度下限不能低于八。

> [!WARNING]
> 没有人能从应用内部缩短锁定时间——超级管理员不能，被锁定的用户也不能。等倒计时结束。如果你把自己锁在了最后一个
> 超级管理员账户之外，请使用下面的恢复方式。

## 如果你被锁在唯一的超级管理员之外 {#reset-admin}

两条应急通道都是你放进数据目录的文件。它们会在下次启动时被消费，并在生效前被删除，因此崩溃绝不会在你背后重复
执行一次。

- `RESET_ADMIN` — 重新生成初始超级管理员的密码，并以与首次启动相同的方式公布新密码，横幅和
  `INITIAL_ADMIN_LOGIN.txt` 两者都有。
- `RESET_MFA` — 只清除初始超级管理员的第二重验证，不动密码。参见
  [第二重验证与账户找回](second-factor#lost)。

两者都需要对主机上数据目录的写权限。这本身*就是*授权：任何拥有该权限的人本来就能读取数据库。审计日志会记录这次
重置且没有操作者，这是诚实的记录——没有人登录来触发它。

## 日常登录 {#daily}

登录界面会提供所有已配置的方式：本地用户名和密码、已接入的目录服务（LDAP/AD）、加入域的桌面上的 Kerberos 按钮，
以及任何已启用的社交登录方。卡片周围有三个控件，各自记在这个浏览器里而不是账户上：

- **语言**切换器 — 英语、马来语、中文和阿拉伯语。阿拉伯语会镜像整个布局。
- **主题**选择器，包含高对比度配色。
- **帮助链接**，打开本手册。它在你登录之前就能用，而那正是你最可能需要它的时候。
