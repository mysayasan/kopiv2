# 会话与提级认证

## 会话存放在哪里 {#where}

在这里登录一次可持续三天，这样在多个应用之间移动的人就不会被反复要求密码。这也让会话本身值得保护，值得能够被立刻
结束。

会话**不是**你在列表里看到的那一行。它存放在缓存中；数据库行的存在，只是为了让那份列表能够被画出来。

```arch
title : 缓存就是会话——数据表只是它们的索引
ext browser : 用户的浏览器，只持有一个会话 cookie
box auth : 每一个请求上都会跑的那次检查
store cache : 缓存。这条记录就是会话本身——删掉它才是结束一个会话。
store table : 数据库。每个会话一行，好让列表能被画出来。单凭一行永远不能证明会话还活着。
box screen : 会话列表，在个人资料和用户界面中
browser -> auth : 每个请求，都带着 cookie
auth -> cache : 这个会话还在吗？
auth --> table : 顺带刷新最后活跃时间
screen -> table : 这个账户有哪些会话？
screen -> cache : ……以及其中每一个是否真的还活着？
```

这就是为什么该列表在最要紧的那个方向上是可信的。行会比它的缓存记录活得更久——一个只是过期的会话会留下它的行——所以
每次列出都会与缓存核对，任何缺失的都会报告为**已结束**。撤销时先删除缓存记录，再标记那一行：如果第二步失败，会话
仍然是死的，这才是安全的失败方向。

## 结束一个会话 {#revoke}

- **你自己的**，在**个人资料**下：每个会话都显示它来自的地址、浏览器、开始时间和最后活跃时间。你当前所用的那个会被
  标注，因此你可以结束其他会话而不结束正在用的这个。**结束其他所有设备上的登录**可以一次做完。
- **别人的**，从**用户**界面。当笔记本丢失或有人离职时，就该用它，而且它在对方下一个请求时就生效——不是等到三天期满。

结束会话并不会停用账户。如果这个账户不该再回来，请同时把它设为停用；否则那个人只会重新登录一次。

两者都会写入[审计日志](audit-log)，结束单个会话与结束全部分别记录。

## 提级重新认证 {#stepup}

一个超级管理员会话可以分配角色、清除任何人的第二重验证、为任何账户签发临时密码，以及导出或恢复整个身份库。仅凭一枚
cookie，就能这样持续三天。

提级认证堵上了这个口子。在一小组操作之前，服务器会要求你证明你仍然掌握着凭据——你的密码，以及在你注册了验证方式时的
一个验证码。它**不是**第二个会话：它是打在你已有会话上的一个短期标记，因此只持有被盗 cookie 的人无法造出它。

它持续**五分钟**，长到足以完成一批管理工作而不必每点一下就重输密码，短到让一台被丢下的笔记本不会仍处于提级状态。

目前它会在以下操作之前被要求：

- 导出或恢复备份，
- 处理密码重置请求（这会签发一个临时密码），
- 清除另一个账户的第二重验证或其安全密钥。

该标记由会话 id 派生并与会话一起存放在缓存中，因此撤销一个会话也会带走它的提级状态，而服务器重启不会让任何人仍处于
提级状态。

两种结果都会被审计——成功的重新认证和失败的那一次。针对提级认证的一连串失败，正是有人在试探一个被盗会话的样子。
