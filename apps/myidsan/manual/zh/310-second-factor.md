# 第二重验证与账户找回

第二重验证只适用于**本服务器自己校验**的凭据，也就是本地账户。目录账户或社交账户的第二重验证属于签发它们的一方，
除非你另行规定；参见下面的[策略](#policy)。

本页中关于你自己账户的一切，都在导航栏底部头像块后面的**个人资料**里。

## 验证器应用 {#enrol}

注册会先把一个验证方式挂起，只有在你证明了一个验证码之后才启用，因此扫错二维码不会把你锁在门外。用任意 TOTP 应用
扫描那个二维码——Google Authenticator、Aegis、1Password——或者在摄像头不方便时手工输入密钥，然后输入它显示的六位数。

验证码是常见的六位数，三十秒一个时间步。*当前*时间步两侧各接受一步，仅此而已，因此时钟偏差超过约一分钟的设备每次
都会被拒绝。如果验证码突然失效而其他什么都没变，先检查手机的时钟。

## 恢复码 {#recovery}

注册时会生成**十个一次性恢复码**，只显示一次，此后不再显示。每一个都能让你跳过第二重验证提示恰好一次，然后就作废。

把它们存在放着验证器的那台手机之外的地方。这就是全部要点：它们所要应对的事件，正是那台手机不在了的时候。

你的个人资料会显示还剩几个。重新生成会替换整套——旧的十个立即失效——并且需要一个当前验证码，因此只掌握你 cookie 的人
无法给自己造一套新的。

使用其中一个会作为独立的动作记入[审计日志](audit-log)，与普通登录分开。一次恢复码消耗是现有最强的信号，表明有人
丢失了验证器——或者接管了它——把它并进"已登录"里，恰恰会把这一点藏起来。

## 安全密钥 {#keys}

硬件密钥或设备内置的验证器（Windows Hello、Touch ID）比验证码更强：它用签名证明自己，它的密钥从不离开设备，本服务器
上也没有任何可被钓走或复制的东西。在**个人资料 › 安全密钥**下添加它们。

有两点需要知道：

- **它们需要 HTTPS。** 在普通的 `http://` 地址上，任何浏览器都根本不会提供这个选项。那是浏览器的规则，不是本服务器
  的。
- **一个账户可以持有多个**，而且应该如此。一把密钥就是一个单点故障；一把密钥加上一个验证器应用，意味着丢掉任何一个
  都只是不便，而不是一套找回流程。

## 强制要求验证方式 {#policy}

在**设置 › 登录**下，策略是以下三者之一：

- **off** — 不提示任何人。已经存在的验证方式在登录时仍然生效。
- **optional** — 仅自助。这是默认值。
- **required** — 范围内的每个人都必须先注册才能使用应用。

"required" 可以收窄到特定角色，这也是常见的形态：对管理员强制，对其他所有人可选。

强制是在密码通过**之后**执行的。欠一个验证方式的人仍会获得会话，并被固定在注册界面上直到添加为止——参见
[首次登录](first-sign-in#gates)中的关卡顺序。这正是该策略可以在人们正在使用服务器时打开的原因：它让人们"添加"一个
验证方式，而不是证明一个他们还没有的。

除非同时打开*应用于目录账户*，否则目录账户**不在**范围内。参见[接入目录服务](directory#mfa)。

## 当验证器不在了 {#lost}

```flow
title : 验证器不在了，如何回到账户里
step lost : 你的验证器丢失、被清除或被更换了
ask codes : 你还留着自己的某个恢复码吗？
ok signin : 用它登录，然后立刻注册一个新的验证器
ask other : 有没有另一位超级管理员能替你处理？
step admin : 他们清除你账户上的第二重验证
ask sole : 被锁定的账户是本服务器唯一的超级管理员吗？
step marker => first-sign-in#reset-admin : 在数据目录里放一个 RESET_MFA 文件并重启
end wait : 去找一位超级管理员——第二重验证无法从登录界面绕过
lost -> codes
codes -> signin : 是
codes -> other : 否
other -> admin : 是
admin -> signin
other -> sole : 否
sole -> marker : 是
sole -> wait : 否
marker -> signin
```

超级管理员清除别人的验证方式之前，必须先重新证明自己的凭据——那正是持有被盗 cookie 的攻击者会去尝试的动作，所以它
位于[提级认证](sessions-and-step-up#stepup)之后。目前这项清除是一次 API 调用，而不是用户界面上的一个按钮。

`RESET_MFA` 标记只清除**初始超级管理员**的验证方式，别的什么都不动——不动密码，也不动其他人的验证方式。它会在下次
启动时被消费并在生效前删除，并且以没有操作者的形式记入审计日志，因为没有人登录来触发它。放下那个文件的人拥有对数据
目录的写权限，而那正是这条记录所指向的东西。

## 忘记密码 {#password-recovery}

登录界面上的**忘记密码**链接适用于本地账户，并且无论账户是否存在，都给出完全相同的答复。一台会说"没有这个用户"的
身份服务器，对任何想要的人来说就是一份目录清单。

在它背后，会发生两件事之一：

- **运维队列。** 一条待处理请求出现在**重置请求**下。超级管理员通过签发一个新的临时密码来处理它，该密码被标记为
  必须修改，然后通过他们信任的渠道交付。这条路径在任何情况下都可用，包括完全没有邮件服务器时——那正是气隙安装的
  常态。
- **自助链接**，仅在配置了内部 SMTP 中继时才有。链接存活半小时，且只为一个账户设置一次密码。

目录账户和社交账户不在这里处理；它们的密码属于各自的提供方，界面会如实说明，而不是假装能处理。
