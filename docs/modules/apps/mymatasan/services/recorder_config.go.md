# Module: apps/mymatasan/services/recorder_config.go

## Purpose

`RecorderConfigBuilder` is the single thing that knows how to turn a camera's stored `entities.RecordingConfig` into a runnable `recording.RecorderConfig`. It replaces three hand-rolled copies of the same struct literal — the app-wiring startup fan-out, the settings-save API handler, and the detect-only stream resolver — that had drifted out of sync.

## Responsibilities

- `NewRecorderConfigBuilder(camera, recordingService, settings, cipher, shredPasses, metrics) *RecorderConfigBuilder` — constructor. `cipher` may be `nil` (encryption-at-rest off); `metrics` may be `nil` (telemetry off). `camera` and `recordingService` are narrow interfaces declared in this file, not the full app services (see Notes).
- `ForRecording(ctx, *entities.RecordingConfig) (recording.RecorderConfig, warning string)` — builds the NVR recorder config for one camera's stored recording config: resolves the RTSP URI (explicit `StreamURL` override, credentials injected, else the ONVIF-discovered URI), reads decoder settings (ffmpeg path, RTSP transport) and at-rest storage settings (codec/quality/`FallbackToCopy`) **live**, and attaches `ShredPasses`/`Cipher`/`Metrics`. `warning` is non-empty (`ErrNoStreamURL`) when the camera is enabled but has no usable stream; the config is still returned (a disabled recorder is legitimate) and the caller is responsible for surfacing the warning.
- `ForDetectOnly(ctx, cameraID) (recording.RecorderConfig, bool)` — builds an AI-only frame source for a camera with no NVR recording. Stream preference deliberately differs from `ForRecording`: `StreamURL` → `LiveStreamUrl` → discovered ONVIF URI (a detect-only stream only needs pixels, not the recording-quality substream). Carries no storage/retention/cipher settings — `ok` is `false` when no usable stream exists.
- Exported const `ErrNoStreamURL` — the exact warning string above, exported so callers/tests can compare against it instead of a copy-pasted literal.
- Unexported helpers `decoderParams` and `credentials` centralize the two settings/camera lookups shared by both `ForRecording` and `ForDetectOnly`.

## Notes

- Declares its own consumer-side interfaces instead of depending on the full app services: `cameraCredentialSource` (one method, `SnapshotSource`) instead of `ICameraService` (39 methods), and `recordingConfigSource` (one method, `GetConfig`) instead of `IRecordingService`. This is the Go idiom of declaring interfaces at the consumer — a test fake is two methods, not forty, and adding a method to the camera/recording service can never break this file. Worth following for the rest of the Tier 2 decomposition (`docs/MYMATASAN_TIER2_PLAN.md`).
- Exists specifically because the three-site duplication cost two real bugs: `ShredPasses` was missing from the settings-save site, so secure shred silently degraded to a plain unlink the moment an operator saved any recording setting; and the at-rest storage codec was captured once at boot by the startup site, so a Settings → Recording codec change never applied until a restart despite the code claiming otherwise. Reading the decoder/storage settings live on every build (rather than once at construction) is what fixes the second bug — a `RecorderConfigBuilder` is built once in `app.go` and reused for the process lifetime, but each `ForRecording`/`ForDetectOnly` call re-reads `IRuntimeSettingsService`.
- Wired in `app.go`: one `RecorderConfigBuilder` is constructed after `recordingService` and passed to the startup fan-out, `apis.NewRecordingApi` (`recorderCfg` field, used by `saveConfig`'s hot-reload), and `monitorSettings.DetectStreamConfig = recorderConfigBuilder.ForDetectOnly`. See `docs/modules/apps/mymatasan/app/app.go.md` and `docs/modules/apps/mymatasan/apis/recording.go.md`.
- Covered by `recorder_config_test.go` (7 tests) using the narrow fakes this file's own interfaces make possible: every `RecorderConfig` field surviving a build (the regression test for the whole file), the storage codec being read live rather than cached, stream URL/credential resolution, the enabled-with-no-stream warning (and its absence when disabled), and the `ForDetectOnly` stream-preference/no-storage-settings behavior.
