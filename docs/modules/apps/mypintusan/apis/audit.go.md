# Module: apps/mypintusan/apis/audit.go

## Purpose

The administrative trail's **read surface**, the **recording helper** every audited handler holds,
and the **fallback middleware** that makes "nothing accepted goes unrecorded" a property of the app
rather than a rule in a review checklist.

## Two tables, deliberately separate

`entities.AccessEvent` answers *"who went through which door, when, and was it allowed"*. This
answers the other half — *"who decided they could"*. One is a decision log written by the controller
at machine rate; the other is a record of human authority exercised over that controller. Filtering,
exporting or ageing one must not touch the other, and merging them would bury a dozen rule changes a
year under a hundred thousand badge events.

## Routes

```
GET /api/audit       list, newest-first, filterable by action/outcome/actor/targetType/targetId/from/to
GET /api/audit.csv   the same listing as a CSV download
```

**There is no delete route and no update route, not even for an administrator.** The value of the
trail is precisely that the person whose actions it records cannot edit it. Age-based retention
exists (`app/audit_retention.go.md`), is reachable only from configuration, archives to disk before
removing anything, and writes its own run into the trail it trimmed.

`/api/audit.csv` is its **own** catalog rule in `services/rbac.go`, not a child of `/api/audit`: the
matrix matches segment-wise, and `audit.csv` is a different segment from `audit`. A rule covering the
listing but not the export is the shape of mistake #224 found — a line of documentation shaped like
policy.

The CSV is written with a **UTF-8 BOM**. Its destination is Excel on somebody's Windows laptop, and
without it every em dash in the trail arrives as mojibake in the one artefact whose whole job is to
be handed to an outsider.

## `Auditor`

What an audited handler holds: the trail plus the parsed trusted-proxy list. A **value, not a
global** — a handler that was never given one records nothing rather than silently reaching a
package-level service that may not exist yet. A nil `Auditor` records nothing and does not panic:
auditing must never be able to fail the action being audited, and that has to hold for a mis-wired
composition root too.

- **The actor comes from the session**, never from a request body — the rule `doors.unlock` already
  followed. An attacker-supplied actor name next to a grant edit is worse than no name at all: it is
  a forged record, and the trail's whole value is that it cannot be authored by its subject.
- **The client IP is resolved through `middlewares.ClientIP`** with the rate limiter's trusted-proxy
  list, so "which hops may set `X-Forwarded-For`" has exactly one answer in this app.

`Success` and `Denied` are the two shapes nearly every call site wants, so no handler spells an
outcome wrong. **Denied — not "error" — is the outcome for a refused administrative act**, recorded
as carefully as an accepted one.

## `NewAuditMiddleware` — the guarantee

Records any **accepted mutating request that reached no handler which audited itself**.

This exists because of the shape of defect this app keeps producing: *the mechanism is right and
nothing reaches it*. Seven benches found the same thing seven times — alarms that could never fire,
a cache that could never expire, a catalog rule that matched no route. A trail instrumented
handler-by-handler has exactly that failure mode built in: it is correct on the day it ships and
silently incomplete the first time somebody adds a route and forgets, and the symptom is an empty
result in an investigation years later.

So **the default is recorded**, and a handler's own entry is an enrichment rather than the only
chance. This is what puts fleet pairing (mounted from shared code this app does not own) and anything
added next year into the trail without a second decision.

| request | recorded as |
|---|---|
| `GET` (any) | nothing — a read is not an administrative act |
| `POST/PUT/PATCH/DELETE` under `/api/notifications` | nothing — see the exemption below |
| accepted (2xx), handler audited it | the handler's own entry, **once** |
| accepted (2xx), nobody audited it | `api.write` / `success`, naming the method and path |
| `403` from a handler's own gate | `api.write` / `denied` |
| any other failure (400, 404, 409, 500) | nothing |

**The one exemption** is marking a feed notification read: a per-user UI state change with no effect
on who may enter anything, generated by the dozen in a busy building. A trail that fills with them is
a trail nobody reads, which is the failure mode that makes an audit log worthless without ever
looking broken. Every entry in that list is a hole, so it is kept short and argued.

**A validation failure is not a security event.** Recording every mistyped form would bury the
entries that are.

### What it does NOT cover, stated rather than glossed

The middleware is registered **inside** the auth and permission middleware, so the principal is in
context — which means **a matrix-level 403 never reaches it** and is not in the trail. Those
refusals are in `api_log`. What it does catch is the refusal that matters more: a handler's own
`administrators only` gate, where the caller passed the matrix and was still turned away.

In this app's *current* catalog no role can reach such a route at all — every admin-gated handler is
already denied to viewer and operator by the matrix — so that branch is proven by
`audit_test.go:TestAuditMiddleware_RecordsAHandlerRefusal` and not on the wire. The live bench
asserts the true statement (a matrix refusal is not in the trail) rather than claiming coverage the
wire cannot give.

## Registration

```go
protected.Use(apis.NewAuditMiddleware(auditor))   // INNERMOST — after auth and the matrix
apis.NewAuditApi(protected, auditService)
```

Order is load-bearing: registered outside the auth middleware there would be no principal to
attribute an entry to. See `app/app.go.md`.
