# Module: apps/myseliasan/entities/managed_node.go

## Purpose

Defines the `ManagedNode` entity: the DB row that represents one `mymatasan` node adopted by this control plane.

## Fields

| Field | Notes |
|---|---|
| `Id` | Auto-increment primary key. |
| `NodeId` | Stable UUID generated by the node on first pairing. Unique key (`ukey:"node_id"`). |
| `Name` | Human-readable node name. The operator's chosen label (set in `AdoptInput.Name`) wins over the node's reported hostname at adoption time. |
| `Description` | Optional operator note shown as a hover tooltip in the side-nav node tree. |
| `Icon` | Pre-installed glyph name for this node shown in the side-nav (e.g. `"camera"`). Set at adoption time from `AdoptInput.Icon`. |
| `Kind` | What this node IS: `"camera"` (a `mymatasan` NVR), `"iot"` (a `myiotsan` sensor hub), or `"door"` (a `mypintusan` access controller). The control plane manages several sorts of appliance and they are NOT interchangeable — a camera node has recordings and live views; a sensor node has telemetry and relays; a door node has doors, badge decisions and an access log. Set from the node's own **adopt reply** (fleet-key-signed, claim-code-gated) — never from the discovery announce's unsigned `Kind` hint (`infra/pairing.Announce.Kind`; see `docs/modules/infra/pairing/packet.go.md`). **Empty means camera**: every node adopted before this field existed is a `mymatasan` node and keeps behaving exactly as it always did. The cross-domain correlator (`apps/myseliasan/services/correlate.go`) resolves a clause's node-kind scope from this field, not from anything an event carries — so a door node cannot claim to be a camera and satisfy a camera-scoped clause. |
| `BaseUrl` | `https://<IP>:<HTTPSPort>` — used to call node APIs. |
| `IP` | Node IP as seen by the control plane at adoption time. |
| `HTTPSPort` | Node HTTPS port. |
| `Token` | Pairing token returned by the node on adoption; stored here for release calls. Tagged `json:"-"` so it is never serialized in API responses. |
| `Fingerprint` | Reserved; not currently used. Identity verification in the implemented mTLS channel uses the certificate CN (node ID), not a pinned fingerprint. |
| `MTLSPort` | The node's mutual-TLS management listener port (heartbeat + release), recorded at adoption from `NodeRegistryConfig.MTLSPort`. Used by the control plane to dial `GET /heartbeat` and `POST /release`. |
| `Lat` / `Lon` | The node's position on the geographic fleet map (see "Fleet Map" in `apps/myseliasan/README.md`), set by an operator dragging the pin via `PUT /api/nodes/{id}/position`. |
| `MapPlaced` | Distinguishes "deliberately positioned" from the zero value — `(0,0)` is a real coordinate (Gulf of Guinea), so a bare `Lat`/`Lon` pair alone can't tell an unplaced node from one parked at null island. `false` (the default for every node adopted before this field existed) means the node is simply absent from the geographic map until someone places it. |
| `CertExpiresAt` | Unix timestamp of the expiry of the last node certificate issued by the fleet CA. Recorded on successful enrollment/renewal so the UI can surface cert health. |
| `SiteId` | The building (`Site`) this appliance **resides in** — `0` means none/standalone. Set via `PUT /api/nodes/{id}/building` (`INodeRegistry.UpdateNodeSite`). A node with a non-zero `SiteId` is drawn as part of that building's marker on the geo map rather than its own pin (assigning a building clears `MapPlaced`); it is deliberately independent of where the node's *cameras* are placed on a floor plan — the box itself may sit in a rack in one building while its cameras are physically elsewhere, though typically both point at the same site. See `entities/site.go.md` and `apis/sites.go.md`. |
| `AutoRenew` | Gates whether this node's certificate is allowed to renew. The node re-enrolls automatically before expiry (unchanged node-side behavior), but `INodeRegistry.Enroll` now refuses that renewal unless this is `true` — a per-node dead-man's switch: a node nobody blesses lets its cert lapse, drops off the control channel, and goes `"lost"`. `false` by default for a newly adopted node (the initial enrollment right after adoption is always allowed regardless of this flag; only a subsequent renewal is gated). Nodes adopted before this field existed are backfilled to `true` exactly once at startup (`INodeRegistry.BackfillAutoRenew`, guarded by the `pairing.autoRenewBackfilled` `ControlSetting`) so an existing fleet — which was renewing automatically — is not surprise-expired by upgrading. Set via `PUT /api/nodes/{id}/auto-renew`. |
| `OwnerRoleId` | The myseliasan `RoleId` that adopted this node. That role has full (admin) access by default, without an explicit `NodeAccessGrant`. Other roles need a grant. `0` means legacy/unknown owner (no default access). |
| `Status` | `"online"` (adopted, reachable), `"lost"` (unreachable / mTLS probe failed), or `"self-dropped"` (node unpaired itself via admin self-drop). |
| `AdoptedAt` | Unix timestamp of adoption. |
| `LastSeenAt` | Unix timestamp of last successful mTLS heartbeat contact. |
