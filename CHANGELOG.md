# Changelog

All notable changes to this project, generated from `changes/` entries on each version bump. Newest first.





































## 2026-07-13 — mymatasan 1.97.2, core 1.56.2 (d57968d)

### Fixed

- **mymatasan,core**: Tier 1 resilience hardening: a new shared infra/safego package gives background goroutines panic recovery (safego.Go, one-shot) and recover-and-restart-with-backoff supervision (safego.Supervise, long-lived loops). Before this, the repo had exactly one recover() anywhere, so a single malformed AI detection in the per-camera vision sampler could panic and kill the entire NVR process (recording, API, everything); the vision monitor, camera/machine health monitors, object-metadata recorder, RTSP recorder's ffmpeg/segment-watch/purge goroutines, the discovery responder, and detector warmup are now wired through safego, and mymatasan's app logger is set as safego's panic sink at startup. In apps/mymatasan/app/app.go, the three near-identical copy-pasted retention purge goroutines (segments+observations, notifications, alerts) were collapsed into one supervised periodic() helper, and previously-swallowed purge errors are now logged. Separately, AI rule cooldown now survives a restart: cooldown state was purely in-process and started empty on every boot, so a busy scene re-fired the instant minFrames was met after any restart, and a crash-restart loop could turn a rule's cooldown into an alert storm, a notification storm, and an ffmpeg clip-extraction storm. A rule's already-persisted LastTriggeredAt (loaded from the DB but never previously read back into the cooldown check, and never written to) now seeds the in-process cooldown map on first sight of the rule (infra/vision/cooldown.go), and the vision monitor now writes the trigger time back via a new IVisionService.MarkRuleTriggered after each sample. A dropped CreateAlert call is now logged instead of silently discarded.
## 2026-07-13 — mymatasan 1.97.1, core 1.56.1 (405d5af)

### Fixed

- **mymatasan,core**: Tier 0 correctness hardening for mymatasan: RTSP segment finalization is now crash-safe (remux writes to a .mp4.part and is only renamed into place after encryption succeeds, so a bare .mp4 on disk is always complete and encrypted, and a .ts sibling always means the segment was never finalized) with a bounded-retry quarantine directory for segments that repeatedly fail to remux; deleting a camera now cascades through a registered cleanup chain (stop recorder/detect-only stream, purge footage, purge object-metadata observations, delete detection rules, purge alert events, delete recording config) and aborts if any step fails, instead of leaving an orphaned recorder and rules running forever; footage retention purge no longer freezes a camera's existing recordings when recording is toggled off, and now drains in batches so a backlog can actually catch up instead of capping at one page per sweep; the recording config API now correctly threads the shredPasses setting into every recorder rebuild it triggers; and the highest-write alert_event table gained (camera_id, created_at) and (created_at) indexes, enabled by a schema-tag change letting one column join multiple index groups.

## 2026-07-13 — myseliasan 1.26.0 (2353e2b)

### Added

- **myseliasan**: MySeliaSan can now discover and add cameras to an adopted node, from the control plane. A new 'Cameras' tab in the node Manage dialog (Adopted Nodes -> Manage) hosts mymatasan's real Discover page: a network scan (ONVIF WS-Discovery, SSDP/UPnP, mDNS, SADP, or a subnet port scan), a manual add-by-address probe, the discovered-device list split into new vs already-added, and the credential dialog that verifies the camera login before saving. ## 2026-07-13 — myidsan 1.12.1, mymatasan 1.96.1, myseliasan 1.25.1, core 1.55.0 (e029430)

### Added

- **myseliasan,core**: MySeliaSan is now a downloadable, installable product on the r450k download page, packaged to full parity with MyMataSan: portable archives (linux/windows/darwin x amd64/arm64), .deb and .rpm packages that install to /opt/myseliasan with a systemd unit and a dedicated service user, a Windows Inno Setup installer that registers a service and generates a one-time admin password, and multi-arch GHCR Docker images. It is pure Go - no ffmpeg, no Python, no model weights - so the payload is just the binary, the web UI and a default config. myseliasan releases under its OWN tag namespace (myseliasan-v<ver>) and is published with --latest=false, so it is versioned and released independently of mymatasan (a bump to either ships that product alone) and never becomes the repo's 'latest' release, which mymatasan's in-app updater reads. GoReleaser OSS cannot derive a semver from a prefixed tag (monorepo/tag_prefix is a Pro feature), so the release workflow hands it a plain version via GORELEASER_CURRENT_TAG, disables its GitHub-release step, and publishes with 'gh release create' itself. The r450k download page now resolves the newest release per product from separate tags (it can no longer use /releases/latest, which only ever returns mymatasan's) and renders a download block per product. Also fixed a packaging blocker: myseliasan's RegisterWebRoutes resolved static/index.html from the CWD-relative BaseDir() rather than deps.HomeDir, so a packaged install (binary and static/ side by side, service working directory elsewhere) would have 404'd on / and /index.html. The self-signed certificate the app generates on first boot is now issued for the running app instead of always claiming CommonName=mymatasan.

### Changed

- **shared,mymatasan,myseliasan,myidsan**: The brand mark and the login screen are now standardized across every app. The shield/eye/checkmark mark moved into the shared UI module as @shared/BrandLogo (with a matching brand.css), so the three hand-copied SVGs can no longer drift; each app supplies only its wordmark and a --brand-mark hue token, deliberately set outside the theme blocks so the brand keeps its identity in light and dark. The geometry and saturation are identical and only the hue moves - mymatasan green, myseliasan steel, myidsan violet - so the apps read as one family while staying tellable apart in a browser tab strip. The password input with its in-field reveal toggle moved to @shared/PasswordField on the same basis. MySeliaSan gained a real favicon (its previous .ico was an unrelated image) and its login, forced-password-change and pending-clearance screens now wear mymatasan's login-panel chrome. MyIDSan had no favicon and no asset pipeline at all; it now has both, and its server-rendered federated sign-in page - the page MySeliaSan hands the browser to during SSO - wears the same card, so the whole federated flow looks like one product. A failed login on that page now re-renders the branded card with the error inline and the username preserved, instead of dumping unstyled text.

### Fixed

- **myidsan**: The federated sign-in page no longer offers Google/GitHub buttons for providers that have no credentials configured. socialButtonsHTML gated the buttons on the provider config block being non-nil, but the stock config.json ships google and github objects with empty client_id/client_secret - a present-but-blank provider is still non-nil, so both buttons rendered and sent the browser to accounts.google.com with an empty client_id. That is an OAuth error on the public internet, and a dead end on an air-gapped intranet, which is where MySeliaSan (whose SSO hop lands on this page) is deployed. A provider is now considered configured only when both client_id and client_secret are non-empty. Covered by tests that assert the buttons disappear for blank credentials and that the page references no external host at all.
- **mymatasan,myseliasan**: The 4953x -> 3953x fleet pairing port move never reached the config that actually ships. deploy/dist/config.json is the default config bundled into MyMataSan's archives, .deb/.rpm, Docker image and Windows installer, and it was left on mtlsPort 49532 with controlPort/mediaPort unset (so they fell back to the Go constants 49533/49534). The dev configs under apps/ were moved to 39532/39533/39534, but a packaged install - the only kind an end user gets - kept the very Windows port conflict the move was made to avoid. deploy/dist/config.json now states mtlsPort 39532, controlPort 39533 and mediaPort 39534 explicitly, and MySeliaSan's new shipped config matches, so a packaged parent and its packaged nodes agree out of the box.

### Security

- **mymatasan**: The in-app self-updater can no longer install a different product over MyMataSan. selectAssets matched a release asset on the '_<os>_<arch>' suffix and file extension alone, with no product prefix. Now that MySeliaSan releases out of the same repository, its archives carry an identical suffix and extension (myseliasan_1.9.0_windows_amd64.zip), so had a myseliasan release ever been the repository's 'latest', every deployed node would have matched that asset, downloaded it, verified it against the shared checksums.txt, and overwritten itself with the control plane. Asset selection now requires the 'mymatasan_' product prefix, so an asset can only ever be this product's archive. myseliasan releases are additionally published under their own tag namespace with --latest=false, so they never become 'latest' in the first place - this prefix check is the second, independent guard.
- **myseliasan**: MySeliaSan no longer falls back to a guessable default superadmin credential. EnsureStockSuperadmin silently substituted the literal password 'admin' whenever the configured localAuth.password was empty, which meant a shipped package with a blank config password would have stood up an admin/admin superadmin on the box that controls the entire camera fleet. The password is now resolved as LOCAL_ADMIN_PASSWORD (ops override), then the config value, and otherwise a strong 16-character per-install password generated from crypto/rand - which is printed to the log and saved to INITIAL_ADMIN_LOGIN.txt in the data dir, exactly as mymatasan already does. A generated password is deliberately not re-applied on subsequent boots, so a restart cannot rotate the credential out from under an operator who just read it out of that file. Adds the lock-out recovery path mymatasan already had: a RESET_ADMIN marker file in the data dir (dropped by the Windows installer's 'reset the admin login' option, or by hand) force-resets the superadmin password on next start, re-enabling the account and re-flagging it must-change; the marker is deleted before the reset runs so it can never fire twice. The login screen also asks the server whether federated sign-in is configured (GET /api/auth/config) and hides the 'Continue with myidsan' button when sso.providerBaseUrl is empty, so a standalone install does not present a primary button that cannot work.
## 2026-07-13 — myseliasan 1.22.0 (92f2b85)

### Added

- **myseliasan**: myseliasan's control plane was a passive relay that only showed a node's status when someone opened the Nodes page; it now proactively alerts on fleet health. The heartbeat reconciler (services/node_registry.go) edge-triggers a notification in the unified feed the instant a node goes online→lost (once, not repeated while it stays lost), when a lost node recovers, and when a node's certificate is within its renewal warn window of expiring or has already expired (deduped per distinct expiry, so a renewal re-arms the warning). The warn window defaults to 7 days and is wired from the existing pairing.renewBeforeHours config (previously only consulted by the node side for its own renewal, so this makes a config key that already existed do double duty rather than adding a new one). A new GET /api/nodes/fleet-status endpoint returns a fleet-wide rollup (total/online/lost/selfDropped/unknown/certsExpiring/certsExpired/certWarnDays), and the Dashboard gained a 'Certs expiring' KPI card fed by it. Separately, ingestNodeEvent no longer silently drops node-pushed event kinds it doesn't recognize (health/disk-full/alert/system/etc.) — it now surfaces them in the notification feed with a best-effort category/severity guess instead of discarding them.
- **myseliasan**: myseliasan gains an immutable audit log of sensitive control-plane actions. A new append-only audit_log table (entities/audit_log.go) and IAuditService (services/audit.go) record who did what, to what, with what outcome, whenever an operator adopts/releases a node (node.adopt/node.release, the latter noting certificate revocation), rotates the fleet key (fleet.key_rotate — the key value itself is never recorded), changes a user's role/enabled state or elevates them to superadmin (rbac.set_role/rbac.set_disabled/rbac.elevate, with before->after role captured), grants or revokes per-node access (node_access.set/node_access.revoke), or sends a mutating command through the reverse node tunnel (node.command, covering the single choke point through which remote wipe/factory-reset/settings-writes reach a node; read-only GET/HEAD tunneled traffic is not audited). A node reporting its own unpairing (node.self_dropped) is attributed to the node rather than an operator. Recording is best-effort and never blocks or fails the action being audited. The trail is readable only via a new superadmin-gated GET /api/audit endpoint (apis/audit.go), with a matching Audit Log page in the SPA (filter by action/target, under Administration) added to the side-nav, App shell, and i18n (en/ms/zh/ar).
- **myseliasan**: myseliasan now implements apphost's ReadinessReporter interface, surfacing fleet-listener health as advisory fields on GET /api/ready: controlChannel (up/down, whether the parent<->node control-channel listener's serve loop is active), connectedNodes (count of nodes currently holding a live control connection), and mediaRelay (up/down, whether the node-camera media relay listener is active). ControlServer gained IsListening() (atomic bool set around its serve loop) and ConnectedCount(); the app module is now stateful, holding the *ControlServer and an atomic media-listening flag set during RegisterAppRoutes, with a new ReadinessStatus method feeding them into the shared /ready handler. This closes the gap where a dead control-channel or media listener still reported the process fully ready.

### Changed

- **myseliasan**: Three control-plane scale/resilience fixes for larger or partially-unreachable fleets. Heartbeat (node_registry.go) previously mTLS-probed nodes without a live control connection one at a time, so a handful of unreachable nodes could blow an entire sweep past the heartbeat interval; probing now runs through a bounded worker pool (heartbeatProbeConcurrency = 16) under a per-sweep budget (heartbeatSweepBudget = 30s) via new probeNodesConcurrently, while DB reconciliation/writes stay serial for the single-writer sqlite store. NodeRegistry.List previously called Get(...,1000,0,...) once, silently truncating the fleet at 1000 adopted nodes and cascading into the operator Nodes list, Scan adoption dedup, and Heartbeat itself; it now pages through the table in nodeListPageSize (500) chunks until exhausted. control_server.go now fails fast when a node's control channel drops mid-command: pending requests are tracked with their owning nodeID (pendingReq), and on disconnect failPending(nodeID) delivers a nil frame to every waiter bound to that node so SendRequest returns the new ErrNodeDisconnected immediately instead of hanging to controlRequestTimeout (30s); node_proxy.go maps it to the same 404 "node is not connected" as ErrNodeOffline. Idempotency keys for tunneled writes were not implemented in this change (would need node-side dedup support in mymatasan), so a non-idempotent write in flight at disconnect time has an unknown outcome and is not automatically retried.
- **myseliasan**: Restyled the superadmin Audit Log page to match the app's standard admin-page layout (settings-panel + header + settings-hint, the same shape as the Users and Roles pages), replacing the bespoke action/target-type <select> filter controls with the shared DataTable's native per-column filtering and sorting. Removed the now-dead .filter-select and .audit-tab.* CSS and 4 i18n keys (audit.allActions/allTargets/filterAction/filterTarget) that backed the old controls.

### Security

- **myseliasan**: The fleet mTLS CA private key, the parent leaf private key, and the fleet PSK previously sat in plaintext in the myseliasan control-plane database (ControlSetting rows) — anyone able to read that database could impersonate the fleet CA or the shared secret and take over every adopted node. These three values are now AES-256-GCM encrypted at rest (reusing the existing infra/atrest module, the same one mymatasan uses for recordings/snapshots/training images) whenever encryption at rest is enabled. New apps/myseliasan/services/secret_store.go adds encodeSecret/decodeSecret helpers (base64(atrest ciphertext) in the TEXT settings column); fleet_ca.go and node_registry.go route the CA/parent private keys and the fleet PSK through them. app.go adds openFleetSecretCipher, which resolves the cipher from the same shared `security` config block mymatasan already documents (encryptAtRest, keyPath, keyProtector, passphrase/passphraseFile/passphraseEnv, recoveryPath) before the node registry is built. Public certificates and the revocation list are unaffected and remain plaintext.

## 2026-07-12 — mymatasan 1.94.0 (26b8f4e)

### Changed

- **mymatasan**: The YOLO worker's stock+custom detection merge (_merge in ai/yolo_worker.py) now gives a taught (custom) model priority over the stock model where it fires: custom detections are kept first, then any stock detection whose box overlaps a kept custom detection (IoU > 0.55) is dropped regardless of label, so e.g. a stock "dog" and custom "cat" on the same animal collapse to one "cat" detection instead of both. Stock detections outside a custom detection's footprint are untouched, so activating a skill still adds its classes elsewhere in the frame rather than blinding stock detection. Because _merge output feeds the whole detection pipeline (not just the Object Search metadata siphon), this also changes AI alert-rule evaluation: a rule targeting a stock class will no longer fire on an object the active taught model has relabeled to a different class.
