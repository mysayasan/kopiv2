# Changelog

All notable changes to this project, generated from `changes/` entries on each version bump. Newest first.


## 2026-07-03 — mymatasan 1.77.0, core 1.45.0 (e88bec2)

### Added

- **mymatasan, infra**: Restores TP-Link Tapo/VIGI talk-back support as a second transport alongside the existing ONVIF audio backchannel, gated by a hardware fingerprint so it never misfires on unrelated devices. New infra/talk/tapo.go + infra/talk/mpegts.go implement the proprietary port-8800 protocol used by Tapo/VIGI consumer cameras that expose no RTSP backchannel (digest-authenticated multipart HTTP session carrying G.711 A-law audio in a minimal MPEG-TS mux, ported from go2rtc pkg/tapo, MIT). infra/talk/talk.go regained Probe8800/isTPLinkStreamd, which only report a camera as talk-capable when its port-8800 response carries TP-Link's 'Streamd'/realm fingerprint. apps/mymatasan/services/talk.go's TalkCapability now falls back to the TP-Link probe when ONVIF fails and reports transport (onvif|tapo|vigi|none) plus needsPassword/hasPassword; a new SaveTalkPassword service method + POST /api/cameras/{id}/talk/password endpoint lets an operator store the TP-Link cloud/speaker password from the camera's Access tab, which only renders when the backend confirms needsPassword. Also fixes a line-crossing direction bug (infra/vision/line_crossing.go): a new lineCrossingBand (~2% of frame) perpendicular dead-band gives each tracked object hysteresis per line, so sub-pixel centre wobble right at the line no longer flips the crossing side every frame and fires in both directions at once, which previously defeated the one-way (forward/reverse) direction filter. The line-crossing preview in the AI rule editor was reworked to match: a single clickable perpendicular arrow plus a shaded 'trigger side' indicator (replacing the old two-arrow diagram and per-rule direction dropdown), and the talk-back mic button now shows a clear 'set the speaker password first' / 'password rejected' message instead of a raw failure when a TP-Link camera needs credentials.
## 2026-07-03 — mymatasan 1.76.0, core 1.44.0 (aa15e10)

### Added

- **mymatasan, apphost, infra**: MyMataSan now ships as a real multi-platform installable appliance instead of only a source checkout. GoReleaser (.goreleaser.yaml + packaging/stage-archive.sh) builds, from one run: linux/windows amd64+arm64 archives bundling the web UI/AI scripts/default config/service files; .deb/.rpm packages (nfpm) that install to /opt/mymatasan, create a dedicated unprivileged mymatasan system user, and install+manage a systemd unit (deploy/nfpm/mymatasan.service + postinstall/preremove/postremove scripts); and multi-arch Docker images (deploy/Dockerfile.release, ghcr.io/mysayasan/mymatasan) with ffmpeg baked in. To support this, infra/apphost gained a home/data directory split (resolveHomeDir/resolveDataDir, MYMATASAN_HOME/MYMATASAN_DATA or generic KOPIV2_HOME/KOPIV2_DATA env overrides): a read-only app root (static assets, AI scripts, default config) is now resolved separately from a writable state root (mutable config, database, recordings, logs, encryption key), with the default config auto-seeded into the data dir on first boot and all writable paths (ResolveWritablePath) falling back to the pre-packaging legacy CWD-relative location when present, so upgrades never orphan existing recordings/keys/DB. If HTTPS is enabled and no certificate exists yet, apphost now generates a long-lived self-signed keypair on first boot (infra/apphost/selfcert.go) covering localhost, configured hostnames, and every local IP, so a fresh install serves HTTPS immediately; deploy/README.md documents bringing your own cert or fronting with a TLS-terminating reverse proxy. The version-bump pipeline (infra/versioning) now also renders and prepends a dated, Keep-a-Changelog-style CHANGELOG.md entry (grouped by change type) for every applied changes/pending batch, wired into .github/workflows/main.yml. Alongside this, two-way audio talk-back shipped for cameras with an ONVIF audio backchannel (mic button in live view, GET/POST /api/cameras/{id}/talk[/offer], new infra/talk package), the machine-health disk mitigation gained an 'overwrite oldest' mode that deletes the oldest recorded segments (with a configurable keep-days floor) to keep recording continuous instead of pausing, and several camera/AI UI fixes landed: the AI rule Test action no longer force-navigates to the notifications page, the zone/line drawing editor gained a Rotate tool, adding a camera now selects the new camera's node directly, the recording status badge distinguishes a detect-only AI frame source from actual recording, and the credential-gate prompt gained a two-step-confirm Remove camera action plus clearer error styling.
- **mymatasan, apphost, infra**: Completes the installer-packaging plan (phases 4-7) on top of the already-shipped GoReleaser packaging: .github/workflows/main.yml now tags the commit v<mymatasan-version> and pushes it whenever a version bump changes the mymatasan app version, then calls a new reusable .github/workflows/release.yml (workflow_call + workflow_dispatch) that checks out the tag, runs GoReleaser, and extracts the newest CHANGELOG.md entry as the GitHub Release notes. mymatasan gained native Windows service support (infra/apphost/service_windows.go detects an SCM-launched process and runs it under svc.Run so services.msc Stop/Start triggers the same graceful shutdown as an OS signal; service_other.go is the no-op stub elsewhere; run.go's Run is now a thin platform dispatcher over the renamed runApp) plus a new Inno Setup Windows x64 installer (packaging/windows/mymatasan.iss) that installs to Program Files, keeps data in %ProgramData%\MyMataSan, and registers the service via sc.exe; release.yml gained a windows-installer job that builds and uploads it. The r450k marketing site added a live Download page (GET /api/downloads in the Cloudflare Worker reads the GitHub Releases API and edge-caches it) so releases surface without a site redeploy. mymatasan also gained an in-app AI runtime installer (new services/python_install.go, Settings -> AI -> Install AI runtime, GET/POST /api/settings/vision/ai-runtime/{status,install,install/status}) that downloads a self-contained astral python-build-standalone interpreter and pip-installs a GPU (CUDA) or CPU PyTorch build plus ultralytics for hosts with no usable Python at all, distinct from the existing Train-in-app 'Install GPU support' flow; the stock yolo11n.pt model is now bundled in every distribution channel (archives, .deb/.rpm, Windows installer) since only the heavy Python/torch runtime is fetched at install time. Finally, mymatasan gained in-app self-update (new services/update.go, Settings -> Version & Health -> Updates, GET /api/system/update, POST /api/system/update/{check,apply}): it checks GitHub Releases on a 6-hour schedule and on demand, and on installs that own their files (portable archive or the new Windows service installer) downloads the matching release archive, verifies its SHA-256 against checksums.txt, swaps the binary and static/ai assets into place, and restarts via the existing apphost.Restarter.
